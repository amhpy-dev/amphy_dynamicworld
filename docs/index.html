Dynamic World
v2.0.0

Introduction

Regional weather, a synced clock and a weather-driven sickness system for Qbox. Rain in Los Santos while it snows on Mount Chiliad, at the same time.

What it does

The server runs a separate sky for every region of the map. Each player sees the weather of the region they're standing in, and it blends as they cross a border. Temperature, humidity and "feels like" come from each region's climate and the time of day, and the sickness system builds on those numbers.

Regions

Draw areas on the map in game, each with its own climate.

Climates

Create climates with sliders: temperature, humidity, weather odds.

Sickness

Cold, rain, heat and grime make players ill, in stages.

Cures

ox_inventory items that treat illness, with progress bars.

Remove other weather scripts

Installation

Four steps. Every database table is created automatically on the first start.

Add the resource

Put amphy_dynamicworld in your resources folder and start it after its dependencies.

ensure ox_lib
ensure oxmysql
ensure qbx_core
ensure ox_inventory
ensure amphy_dynamicworld

Remove your old weather sync

Stop qb-weathersync, Renewed-Weathersync or vSync. Other resources that call their exports keep working, see Compatibility.

Add the cure items

Only if you use cures. Add each item from data/cures.lua to ox_inventory, pointing it at the export. See Cures for all seven.

['antibiotics'] = {
    label = 'Antibiotics',
    weight = 50,
    client = { export = 'amphy_dynamicworld.useCure' },
},

Start the server

On the first start the regions and climates from data/regions.lua and data/climates.lua are written to the database. Join, then open the editor with /weatherregions.

Permissions

Admin commands and the editor are restricted to adminGroup in data/settings.lua, group.admin by default.

Configuration

Every setting lives in data/, one file per area. Each file returns a plain table.

Toggles

Switch whole systems on or off.

return {
    enable = {
        weather = true,        -- regional weather, wind and blackouts
        time = true,           -- synced day/night cycle
        sickness = true,       -- catching, worsening and recovering from illness
        cures = true,          -- ox_inventory items that treat sickness
        regionNotify = false,  -- tell players when they cross into another region
        compatibility = true,  -- answer qb-weathersync and vSync calls from other resources
    },

    adminGroup = 'group.admin',
}

Translations

Every message players and admins see is in locales/en.json. Copy it to your language's code, translate the values, and set ox_lib's locale.

Keys missing from your file fall back to English.

Regions

Areas of the map that share a climate. Every region runs its own weather, all at once.

How it works

GTA can only show one sky per player, so the server keeps a separate weather for every region and each client applies the one it's standing in. Two players a few kilometres apart really do see different weather at the same moment.

  • A border only counts once you've stayed past it for border.dwell ms, so standing on the line doesn't flicker.
  • Crossing blends the sky over blend.region seconds. A teleport snaps instead.
  • Anywhere no region covers, like the open sea, uses the default region.

The editor

Run /weatherregions. The Overview page shows every region on the map with its weather and temperature. Click one to edit it.

FieldWhat it does
ClimateWhich climate the region rolls its weather from.
ShapeA polygon drawn corner by corner, or a circle with a radius.
PriorityWhere regions overlap the higher one wins. On a tie the smaller one does.
Altitude floorThe region only applies above this height, so a summit can snow while the forest below doesn't.
WeatherForce a weather, set it back to auto, or skip to the next.
Power cutTurns the lights off in this region only.

Placing a region

  • On the map: New region, pick a climate, click each corner, then Finish or double-click.
  • In game: "Walk the corners" lets you click corners in the world. "Aim and place" drops a circle where you look, scroll to resize.
  • Moving: shift-click the map to move the selected region.
Names

Region and climate names are capped at 20 characters so they fit everywhere in the panel.

Climates

What a region is like. Create and edit them in the panel; changes go live for every player as soon as you save.

Fields

FieldRangeWhat it does
Day / Night−30 to 50 °CTemperature at the hottest (15:00) and coldest hour of a clear day.
Humidity0 to 100 %Base humidity. Weather and night push it up or down.
Weather lasts5 to 120 minEach spell lasts a random time between the two, in real minutes.
Wind0 to 3×Multiplies the wind ranges in data/weather.lua.
Holiday weatheron / offOff ignores the Halloween and Christmas seasons, for tropical climates.
Weather odds0 to 100 eachHow likely each weather is. A weather at 0 never happens on its own.

How weather is picked

Weather follows a transition graph in data/weather.lua, so clouds come before rain. Each step is weighted by the climate's odds, which is why a desert rarely gets past the clouds. surprise (12% by default) lets a change skip the graph so every listed weather can appear.

Defaults

The five climates that ship are yearly averages of real places.

ClimateBased onDay / nightHumidity

Deleting

A climate can't be deleted while any region uses it. Move those regions to another climate first.

Weather & time

Blending, seasons, blackouts and the shared clock.

Blending

blend = {
    weather = 45.0, -- seconds to blend when a region's weather changes
    region = 20.0,  -- seconds to blend when crossing into another region
},

border = {
    dwell = 2500,             -- ms past a border before it counts
    checkInterval = 500,
    teleportDistance = 400.0, -- further than this between checks snaps
},

Seasons

Between two dates every region holds one weather, except climates with holiday weather turned off.

seasons = {
    { weather = 'HALLOWEEN', from = '10-25', to = '10-31' },
    { weather = 'XMAS', from = '12-01', to = '12-31' },
},

Blackouts

Three levels, combined: city-wide, per region, and per player. Toggle them with /blackout, the City power chip in the panel, or the exports.

Time

One clock for the whole map. Between corrections every client runs the clock itself, so it ticks smoothly.

return {
    start = { hour = 9, minute = 0 },
    dayLength = 48,     -- real minutes per in-game day, 0 stops the clock
    frozen = false,
    transition = 8000,  -- ms to ease into a time set with /time
    resync = 30000,
}

Interiors & shells

Stop syncing for a player inside a shell or IPL, give them their own weather and time, then hand control back.

Holds

Each caller pauses with its own id. Sync only resumes once every hold is released, so housing and an MLO script can't fight.

exports.amphy_dynamicworld:pauseWeatherSync('my_housing', {
    weather = 'CLEAR',
    time = { hour = 12, minute = 0 },
    freeze = true,
    blackout = false,
})

exports.amphy_dynamicworld:resumeWeatherSync('my_housing')

Anything left out falls back to interior in data/weather.lua.

From the server

exports.amphy_dynamicworld:setPlayerSync(source, false, { weather = 'CLEAR' })
exports.amphy_dynamicworld:setPlayerSync(source, true)
Existing housing scripts

Scripts that fire qb-weathersync:client:DisableSync / EnableSync or vSync:toggle work as they are.

Sickness

Exposure builds while conditions are bad. Past a threshold players can catch something, and it worsens in stages until they recover or take a cure.

Exposure

Every tickInterval (10 s) each factor adds to a 0–100 exposure pool, multiplied by its weight.

FactorWhen it counts
coldFelt temperature below tooCold (5 °C).
heatFelt temperature above tooHot (32 °C).
wetOutdoors in rain or snow.
humidityAbove tooHumid (85%).
scumminessGrimy parts of the map, from GTA's own zone data.
contagionWithin 4 m of a contagious player.

Indoors

Inside a building, or a vehicle with its roof up, the player feels indoors.temperature and indoors.humidity instead of the weather, stays dry, and recovers faster.

Stages

Severity runs 0–100. Each sickness has stages that apply once severity reaches their threshold.

Stage keyEffect
coughCoughs or sneezes on a random timer, heard by players nearby.
movementWalk clipset, like move_m@injured.
sprintStaminaBelow 1.0, shorter sprints before the key is blocked.
sprintSpeedRun speed multiplier.
greyscale / timecycleScreen effects.
shakeCamera shake.
healthDrainHealth per second, never below minHealth in data/effects.lua.

Shipped sicknesses

Common Cold, Influenza, Heat Stroke, Hypothermia and Respiratory Infection, each with mild, moderate and severe stages. Add your own in data/sicknesses.lua.

Characters

Sickness is saved per qbx character (citizenid). It loads when the character spawns, resets on logout, and doesn't progress in the character menu.

Try it

/dwshowcase walks you through every stage of every sickness, then puts your real state back.

Cures

ox_inventory items that treat sickness, with an ox_lib progress bar and animation.

Items

Add each of these to ox_inventory/data/items.lua. The export plays the progress bar and only consumes the item once it completes.

['cold_medicine']   = { label = 'Cold Medicine',     weight = 50,  client = { export = 'amphy_dynamicworld.useCure' } },
['antibiotics']     = { label = 'Antibiotics',       weight = 50,  client = { export = 'amphy_dynamicworld.useCure' } },
['flu_shot']        = { label = 'Flu Shot',          weight = 50,  client = { export = 'amphy_dynamicworld.useCure' } },
['water_bottle']    = { label = 'Bottle of Water',   weight = 500, client = { export = 'amphy_dynamicworld.useCure' } },
['electrolytes']    = { label = 'Electrolyte Drink', weight = 500, client = { export = 'amphy_dynamicworld.useCure' } },
['hot_coffee']      = { label = 'Hot Coffee',        weight = 300, client = { export = 'amphy_dynamicworld.useCure' } },
['thermal_blanket'] = { label = 'Thermal Blanket',   weight = 800, client = { export = 'amphy_dynamicworld.useCure' } },
Don't set usetime

Leave out ox_inventory's own usetime and anim. The cure plays its own progress bar, and both would run.

antibiotics = {

Effects

Coughs, sprint limits and screen effects, set in data/effects.lua.

Coughs

A stage's cough picks an animation by key. Coughs use the ped's own voice (PLAY_PAIN), so there are no audio files, and nearby players hear them.

cough_heavy = {
    dict = 'timetable@gardener@smoking_joint',
    clip = 'idle_cough',
    duration = 4000,
    pain = PAIN.cough,
    painAfter = PAIN.wheeze,
},

Test a voice line with /dwpain <id> and an animation with /dwcough <anim>.

Stage changes

onStageChanged runs whenever a player moves between stages. Replace it to use your own notifications.

Database

Everything is plain columns, so you can read and edit it in HeidiSQL. Tables are created on first start; sql/install.sql has them if your user can't create tables.

TableWhat's in it
dynamicworld_regionsOne row per region: name, climate, shape, centre, radius, priority, floor, enabled.
dynamicworld_region_pointsOne row per polygon corner, in order.
dynamicworld_climatesOne row per climate: name, colour, temperatures, humidity, duration, wind, holiday weather.
dynamicworld_climate_weathersOne row per weather in a climate, with its weight.
dynamicworld_sicknessOne row per character with any sickness, exposure or immunity.
Saving

A region or climate and its child rows are saved in one transaction, and deleting a parent removes its children. Sickness writes are batched once a minute and on logout.

Editing by hand

Changes made directly in the database are read on the next restart. Changes made in the panel go live straight away.

Compatibility

Drop-in surfaces for the weather resources this replaces. Turn off with enable.compatibility in data/settings.lua.

qb-weathersync

Its server exports and events work. Getters answer for primaryRegion in data/weather.lua and setters act on every region. To answer exports['qb-weathersync'] calls, uncomment provide 'qb-weathersync' in fxmanifest.lua.

Renewed-Weathersync

GlobalState.weather keeps its shape, so HUDs reading it still work. They show the primary region's weather; use getConditions() for the player's own.

vSync

vSync:toggle pauses and resumes sync like it always did.
